# MVP 开发路线图

每个阶段都以“配置成功、编译成功、测试通过、实际启动验证”作为进入下一阶段的门槛。

## 阶段 0：环境与工程骨架（已完成）

- 确认 Qt、CMake、Ninja、MSVC 与 Windows SDK。
- 建立 C++20 / Qt Quick / CMake 工程。
- 建立应用组合入口、最小 QML 壳和启动冒烟测试。
- 建立 Git 忽略规则、架构与路线文档。

完成标准：Debug 构建成功，`lingnest_startup_smoke` 通过，程序能显示最小窗口。

## 阶段 1：透明桌宠窗口与静态角色（已完成）

- 实现无边框、透明、置顶且不占普通任务栏项的 `PetWindow`。
- 加载角色包和渝爱静态 PNG。
- 实现拖动、多显示器边界钳制和窗口位置持久化。
- 验证 Windows 不同 DPI 与屏幕布局。

完成标准：重启后恢复有效位置；拔掉副屏后角色不会留在屏幕外。

当前已通过自动化窗口属性、拖动、边界钳制和重启恢复测试。当前开发机只有一个活动显示器，真实双屏拔插场景保留到发布候选阶段做硬件验证。

## 阶段 2：动画与有限状态机（已完成）

- 实现 `PetState`、`PetStateMachine`、动画目录和 PNG Sequence 播放器。
- 接入 Idle、Blink、Walk、Talk、Happy、Wave、Daze、Sleep、Thinking。
- 实现本地随机调度、最小打扰间隔和暂停开关。
- 为状态转换和角色清单增加单元测试。

完成标准：动画时序来自角色包，切换不跳位，状态机测试通过。

当前实现包含通用动画目录、`IAnimationPlayer`、PNG Sequence 播放器、完整桌宠状态机和多计时器本地调度器。窗口会随 Walk 真实移动并在屏幕边缘转向；Daze、Blink、Wave 和 Sleep 均有明确入口。播放器支持 `loop_start_frame`，可把入睡前导段与持续呼吸循环分开。渲染测试会抓取真实 QML 窗口并逐一验证新接入动作。

## 阶段 3：交互与桌面气泡（已完成）

- 单击反馈、双击打开聊天、右键菜单和拖动手势仲裁。
- 菜单提供聊天、设置、切换角色、暂停活动与退出。
- 气泡根据屏幕边缘自动翻转并定时隐藏。

完成标准：单击、双击和拖动不互相误触；右键退出可靠。

当前已通过真实 QML 窗口测试验证手势路由、拖动不误触、右键菜单、暂停/继续与退出信号。气泡会根据桌宠位于工作区顶部或底部自动翻转，并始终钳制在当前屏幕内。

## 阶段 4：轻量对话交互（已完成）

- 实现贴近桌宠的无边框单行输入浮层。
- Enter 发送、Esc 收起；发送后切换为思考气泡和角色回复气泡。
- 输入与回复浮层跟随桌宠，并自动避开桌面可用区域边界。

完成标准：完整的输入、思考和回复链路可测试，UI 不阻塞。

当前对话入口是紧凑的桌面输入条，不显示传统消息列表窗口；历史仍由控制器与 SQLite 保存。输入提交、清空取消、浮层生命周期、回复气泡和 Thinking → Talk 状态联动均已测试。正式 Provider 抽象在下一阶段接入。

## 阶段 5：AI Provider（已完成）

- 定义 `IAIProvider` 与异步请求结果。
- 实现 OpenAI-compatible Chat Completions Provider。
- 配置 Base URL、Model、Temperature、Max Tokens 与安全凭据。
- 处理取消、超时、HTTP、JSON、API 与离线错误。

完成标准：成功与失败路径都有测试替身覆盖，GUI 线程保持响应。

当前已实现 `IAIProvider`、OpenAI-compatible Chat Completions Provider、角色 prompt 与内存会话上下文。设置页可配置 Base URL、Model、Temperature、Max Tokens 和超时；API Key 只存入 Windows Credential Manager。Provider 的成功、配置错误、取消、超时、传输错误、HTTP/API 错误与非法 JSON 均由本地测试服务器覆盖，聊天控制器不会阻塞 GUI 线程。

## 阶段 6：SQLite 记忆（已完成）

- 实现 schema migration、会话记录和用户资料。
- 加载最近 N 条对话。
- 识别明确的“记住……”指令并保存结构化 Memory。
- 实现 PromptBuilder 的顺序与预算裁剪。

完成标准：关闭并重启后聊天记录仍在，Prompt 不无限增长。

当前已实现带 `user_version` 迁移的 SQLite 仓储，包含 `conversation`、`memory` 与 `user_profile` 三类数据。聊天控制器启动时恢复最近 40 条消息，成功的用户与助手消息都会持久化；明确的“记住……”内容会分类并去重写入长期记忆，姓名、生日和所在地会结构化写入用户资料。`PromptBuilder` 固定按角色人格、记忆/资料、最近对话和本轮消息组合请求，优先保留相关记忆和较新的对话，并施加硬字符预算。仓储重开、对话恢复、记忆去重、清空会话保留长期记忆以及 Prompt 顺序/裁剪均有自动化测试覆盖。

## 阶段 7：稳定性与发布候选（首包已完成，待跨环境签收）

- 完善日志脱敏、异常恢复与退出清理；继续加固已实现的单实例行为。
- 使用 `windeployqt` 生成可分发目录并在干净 Windows 环境验证。
- 完成多显示器/DPI、断网、损坏配置与数据库升级测试。
- 补充隐私说明、素材授权记录和用户文档。

完成标准：第一阶段 14 项 MVP 验收全部通过，再进入语音、视觉或技能等第二阶段能力。

当前已完成配置损坏备份恢复、SQLite 完整性检查与安全重建、AI 错误密钥脱敏、EXE 版本资源、Release 自动化测试、`windeployqt` 部署、应用本地 VC++ 运行库、发布敏感文件门禁、用户指南、隐私说明、素材记录，以及 `v0.1.3` 候选版单文件安装程序、便携 ZIP、清单与校验和生成。Debug 与 Release 的 15 项自动化测试均通过，便携部署目录烟雾启动通过；安装/卸载仍需在不限制安装类进程的干净 Windows 设备上签收。

仍需在独立干净 Windows 设备上人工签收通知区域、窗口合成与启动体验，并在真实双显示器/DPI 热插拔环境复核。当前首包由 Qt 5.15.2 兼容工具链构建；正式公网 HTTPS 发行应切换到 Qt 6，避免引入已停止维护的 OpenSSL 1.1.1。以上跨环境项完成后，阶段 7 才可标记为最终签收。

## 明确不进入本轮 MVP

语音识别、TTS、屏幕理解、复杂 Agent、插件市场、云账号、多人社交、3D、Live2D、向量数据库和角色商店均不在第一阶段实现范围内。
